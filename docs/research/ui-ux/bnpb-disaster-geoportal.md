# BNPB disaster geoportal (Geoportal Kebencanaan Indonesia)
URL: https://gis.bnpb.go.id/ · Audited: 2026-11-14 · Tier: 2 · Supplement: Borneo

Method note: the BrowserOS neo browser session was not connected this audit (every `mcp__browseros-neo__*` call — `name_session`, `tabs`, `run` — returned `fetch failed`; retried 3× across the session). No interactive walkthrough or screenshots were possible. Every observation below instead comes from the live site fetched directly during this session: `curl` of the public pages (`gis.bnpb.go.id` wrapper, `/databencana/src/Map.php`, `/databencana/tabel/pencarian.php`, `data.bnpb.go.id`) and the portal's public ArcGIS sharing REST API (`/arcgis/sharing/rest/…`), plus read-only GET queries against the Pantauan Bencana data API. ## Summary
BNPB's geoportal is an ArcGIS Hub ("Geoportal Kebencanaan Indonesia") whose homepage presents Indonesia's official hazard taxonomy as nine keyword category-cards — banjir, gempabumi, gunung api (typo'd "gunugapi" in the card keyword), **karhutla**, tsunami, longsor, angin, kekeringan, abrasi — with fire (karhutla) as a first-class national disaster class: it has its own homepage card, a dedicated `data.bnpb.go.id/data/karhutla2026` dashboard (linked from the hub's Dashboards page; Cloudflare-challenged to this session's fetches, contents unverified), InaRISK exposure layers (`Penduduk_Terpapar_Karhutla_inaRISK`), and 92 karhutla/kebakaran catalog items. What it does best for IGNIS is the thing the brief picked it for: every incident record in the live Pantauan Bencana API carries the **official admin hierarchy as codes** (`id_prov`, `id_kab` = Kemendagri codes, plus `kabkot` name and free-text Kecamatan/Desa), an official disaster-class id (`id_jenis_bencana: 106` = KEBAKARAN HUTAN DAN LAHAN), decomposed date fields, and **record-level provenance** (`sumber` names the reporting BPBD Pusdalops office with WhatsApp/phone/email). The UI itself is a fragile shell — a wrapper domain iframing the Hub, Hub pages iframing legacy PHP apps — with no linked views, no comparison, no mobile viewport, Bahasa Indonesia only, and a province dropdown that lists every Kalimantan province twice (Title Case and ALL CAPS).

## Patterns worth taking
- **Karhutla as a first-class hazard category**: the national portal's homepage gives fire equal standing with flood and earthquake as one of nine keyword cards, and fire gets its own dedicated dashboard (`karhutla2026`), its own InaRISK exposure layer (Penduduk_Terpapar_Karhutla) and its own hazard/vulnerability index layers. For IGNIS: in a multi-hazard region, fire deserves top-level nav and named products, not a buried layer. Serves all three users.
- **Kemendagri-coded incident records**: every incident stores the admin chain as official codes (`id_prov: 62`, `id_kab: 6207`) alongside names, so records survive province splits and renames (the pre-2012 Kalimantan Utara problem `gwis.md` documents). For IGNIS: the region panel should select and store admin codes, never bare names. Serves Scientist + Land manager.
- **Record-level provenance (`sumber`)**: each incident names the reporting BPBD Pusdalops office with WhatsApp/phone/email — source transparency at the row level, not a global methodology page. For IGNIS: the per-Hotspot analog (sensor, confidence, time) plus a visible source line on every aggregate — the B4 precedent. Serves Scientist.
- **State-in-GET-URL map**: the Pantauan map's full filter state (`startDate`, `endDate`, `provinsi`) lives in the URL, so any view is shareable/bookmarkable as a link. For IGNIS: Burning Calendar + Area-of-Interest state must round-trip through the URL (as `sentinel-hub.md` already argued). Serves all three.
- **Hazard → Vulnerability → Risk layer triad**: the map's layer tree groups InaRISK products as Peta Bahaya / Peta Kerentanan / Peta Risiko — a clean conceptual ladder from threat to exposure to risk. For IGNIS: the same ladder organizes context layers (Hotspots = detection; peat/concession = vulnerability; population = exposure) in one panel. Serves Land manager.
- **Cautionary: three UI generations nested in iframes (avoid)**: wrapper domain → ArcGIS Hub SPA → legacy PHP map/table, plus an ArcGIS Dashboard that is a one-widget shell around the PHP map. State cannot cross the iframe boundaries, so no view is linked to any other and each embed re-implements navigation. For IGNIS: one app, linked views, no embed-in-embed.
- **Cautionary: dirty canonical lists (avoid)**: the province dropdown lists every Kalimantan province twice in different casings; a hazard card keyword is typo'd ("gunugapi"); two disaster-class vocabularies (LETUSAN/ERUPSI GUNUNG API) coexist in one page's markup. For IGNIS: one coded, deduplicated admin/class reference for the whole Coverage Area — this is the B1 trap in miniature.
- **Two official counts, no bridge**: BNPB reports karhutla *incidents* (30 in Kaltim, Aug 2026) while SiPongi reports satellite *Hotspots* (thousands nationally) — both official, wildly different by definition, and neither site references the other. For IGNIS: the about/method view must define Harmonized Hotspot Count against both worlds and say why the numbers differ. Serves Scientist + Land manager.
